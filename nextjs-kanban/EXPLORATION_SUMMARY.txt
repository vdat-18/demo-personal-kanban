KEY FINDINGS
================================================================================

ARCHITECTURE PATTERN: Server Components ↔ Client Components Split
- Pages fetch from DB server-side (no browser JS)
- Clients handle all interactivity
- Prevents sending Date/complex objects to browser

COMMUNICATION: REST API + SSE Streaming
- Standard CRUD: GET/POST/PUT/DELETE to /api/tasks, /api/projects, etc.
- Agent chat: POST /api/agents/stream (Server-Sent Events)
- Tokens stream one-by-one for real-time feel

STATE MANAGEMENT: 3 Layers
- React Query: Caches server data, handles optimistic updates
- Zustand: Modal/form state (ephemeral, not persisted)
- useState: Component-local state initialized from server props

DATA FLOW: Task Creation
1. User creates project → POST /api/projects
2. User chats with AI (Planner) → memory only
3. User clicks "Generate Tasks" → POST /api/agents/generate-tasks
4. AI returns JSON tasks → backend batch-creates with transaction
5. User navigates to Kanban board to execute tasks

SECURITY: Backend-Only Prompts
- Frontend sends: raw user input + context IDs
- Backend builds: full prompts with DB context
- Prevents prompt injection attacks

DATABASE: 3 Tables (Prisma ORM)
- Project: id, name, description, createdAt, updatedAt
- Task: id, title, description, status, priority, projectId, createdAt, updatedAt
- Conversation: id, taskId, messages[], result, tokenUsage, createdAt

STATUS MAPPING: Database ↔ Frontend
- TODO ↔ "todo"
- IN_PROGRESS ↔ "doing"
- IN_REVIEW ↔ "review"
- DONE ↔ "done"
- BLOCKED ↔ "cancelled"

VALIDATION: Centralized Zod Schemas
- All schemas in lib/validations/schemas.ts
- All API inputs validated with .parse()
- Returns detailed error messages for debugging

AGENT SYSTEM: 3 Roles
1. Architect: Breaks down projects, generates tasks
2. Developer: Implements features, solves problems, creates tasks
3. Reviewer: Reviews code, identifies issues

IMPORTANT GOTCHAS
================================================================================

⚠️ Next.js 16: params is a Promise
   const { id } = await params  ✓ CORRECT
   const { id } = params        ✗ WRONG

⚠️ Date Serialization: Convert to ISO string
   createdAt: date.toISOString()  ✓ CORRECT
   createdAt: date                ✗ WRONG

⚠️ Database vs Frontend Enums: Don't mix
   Database: TaskStatus.TODO
   Frontend: "todo" (string)

⚠️ Backend-Only Prompts: Security rule
   Send: { role, userMessage, taskId }
   Backend builds: full prompt with DB context

⚠️ Centralized Validation: Use lib/validations/schemas.ts
   Don't duplicate schemas in route files!
