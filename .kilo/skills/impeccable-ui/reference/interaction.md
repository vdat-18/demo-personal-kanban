# Interaction

## Goals

- Clear affordances
- Stable action hierarchy
- Low-friction workflow

## Rules

- Primary, secondary, and destructive actions must be clearly different.
- Hover, focus, disabled, and loading states must be easy to understand.
- Hide/show controls should be compact and predictable.
- Empty states should suggest the next action when possible.
- Avoid interaction patterns that make dense surfaces harder to read.

## In Practice

- Planning controls should sit close to the planning header, not buried in the input area.
- Toggle buttons should feel like utilities, not primary CTAs.
- Approval and dismiss actions must be easy to distinguish.
