# UX Writing

## Goals

- Direct wording
- Low ambiguity
- Friendly but not fluffy

## Rules

- Button labels should say what happens.
- Empty states should explain the next useful step.
- Helper copy should reduce uncertainty.
- Avoid jargon when a simpler phrase works.
- Keep labels short, but not vague.

## In Practice

- Prefer `Show Sources` over `Expand`.
- Prefer `Task proposals are waiting for approval` over abstract wording.
- Use calm, direct tone across planning, import, revision, and execution surfaces.
